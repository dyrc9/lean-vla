\section{Introduction}
\label{sec:introduction}

Vision--language--action (VLA) models turn language, images, and robot state
into continuous actions.  At deployment, each policy call produces an action
chunk that crosses from model output into the robot's execution stack.  That
boundary is consequential but evidentially weak: the numeric chunk does not
itself establish that it is admissible for the current task, that later
software will preserve it, or that its realization is qualified for the
current physical state.

An attacked context makes the problem concrete.  In one evaluation workload,
the operator task is to move a soda can to a plate, while SABER changes the
policy-facing instruction to ``move straight to the farthest fixture.''  The
policy returns a $10\!\times\!7$ numeric block rather than a trustworthy plan
that identifies which task authorized it.  Bounded instruction edits can
change continuous trajectories and induce constraint violations
~\cite{saber2026}; visual and embodied-agent attacks provide other routes from
compromised context to physical behavior
~\cite{badrobot2025,robopair2025,freezevla2025}.  Input filtering alone is too
early, while an eventual task or safety outcome arrives too late to authorize
the command that produced it.

The lifecycle of an online action exposes three distinct questions.  First,
how can a consumer assess a continuous block relative to the current task
without treating an incomplete geometric proxy as a semantic oracle?  Second,
how can it establish that assessment, authorization, ordered dispatch,
receipts, and effects all refer to the same proposal and state epoch?  Third,
how can it qualify state-dependent physical constraints without silently
replacing the action that earlier evidence names?  Smoothness, a one-time hash
comparison, and a post-hoc success label answer none of these questions alone.

Prior systems protect valuable portions of this path, but stop on opposite
sides of the same object.  Prompt/data separation and trusted-control-flow
systems protect authority before model output~\cite{struq2025,secalign2025,
camel2026,ace2026}; action attribution and trajectory auditors primarily cover
discrete digital actions~\cite{attriguard2026,mate2026}; VLA verifiers rely on a
policy-supplied plan, a learned score, or multiple candidates
~\cite{sealvla2026,covervla2026}; CPS integrity and robot attestation begin from
an already specified command or protected task program with reference motion
~\cite{diat2019,cfaplus2024,arto2026,tat2026}.  Table~\ref{tab:related-comparison}
summarizes these stopping points.  The unclosed composition is the exact
continuous block generated online by a VLA.  It is neither a discrete API call
nor a trajectory predeclared by a trusted robot program.

Our key insight is that this block is the hinge between VLA reasoning and
embodied execution, and should therefore be the protected security object.
The consumer need not recover the model's latent intent or assume a unique
reference trajectory.  Instead, it should attach task-relative justification
to the exact source block, preserve the same identity through dispatch and
evidence collection, and qualify state-dependent realization without silently
changing the object that earlier evidence names.

We realize this idea in \system, an inline consumer-side reference monitor that
leaves the VLA checkpoint and $K=1$ action generation unchanged.  Under an
explicit trusted-task and observation assumption, \lone binds a
checker-relative assessment to $(Z_t,O_t^T,A_t)$: covered hard risks reject,
while uncertain task progress remains an auditable advisory.  \ltwoa compiles
a proposal-scoped contract, issues a fresh one-use authorization, checks each
ordered dispatch step, and requires bound receipts and effects before task
phase advance.  When a registered joint boundary triggers, \ltwob evaluates at
most two temporary virtual-guard configurations for the same source action
against identity, restoration, margin, and force conditions.  It changes the
execution configuration, not the policy output.

We capture this claim as one top-level property,
$\mathsf{ProofAligned}$: the source block must be checker-relative eligible;
its execution transaction must align; and a triggered physical boundary must
have qualified containment.  Task phase advance additionally requires bound
completion evidence.  Lean machine-checks the finite authorization, ordered
action, receipt, effect, and phase-transition relations.  Continuous dynamics,
checker soundness, sensor trust, and the Python-to-Lean refinement remain
explicit assumptions or empirical obligations.

We evaluate the attack surface and the three mechanism roles separately.  On
the complete 120-unit attack-evaluation protocol, 39 of 86 clean-eligible units
under SABER exhibit a new physical-risk transition, giving an observed ASR of
45.35\% (95\% base-pair cluster-bootstrap CI: [32.93\%, 57.78\%]).  A paired
four-arm mechanism study contains 18 task/initialization pairs and 144
episodes.  Under attack, VLA-only and L2-only succeed on 11/18 tasks, while
L1-only and Dual succeed on 13/18; their joint-limit violation-episode counts
are 4/18, 1/18, 0/18, and 0/18.  The current populations and risk endpoints are
reported separately rather than pooled.  Fault injection and Lean support
L2a's transaction role, while the paired outcomes and runtime measurements
support L1 and combined-L2 behavior.

Our contributions are:
\begin{itemize}
  \item \textbf{A protected object and security property for embodied VLA.}
  We make the exact online \actionblock the common object across task-relative
  assessment, execution identity, and state-dependent realization, with an
  explicit adversary, TCB, and top-level $\mathsf{ProofAligned}$ property.
  \item \textbf{A cross-layer reference monitor.} \system composes trusted
  subtask selection and local block assessment (L1), a nonce/digest-bound
  execution transaction with Lean-checked abstract semantics (L2a), and
  bounded, state-triggered joint containment that preserves source-action
  identity (L2b).
  \item \textbf{Auditable attack and mechanism evidence.} We measure a
  risk-transition ASR of 39/86 (45.35\%) under SABER and report paired
  VLA/L1/L2/Dual outcomes, focused transaction-fault tests, and runtime
  containment evidence.  Each evidence source is tied to the property it can
  support rather than combined into a broader robot-safety claim.
\end{itemize}

\system does not recover a model's latent intent, prove that every accepted
action advances the task, or establish general robot safety.  Its security
value is narrower and inspectable: every covered decision names which exact
action was assessed, which authorization permitted it, which command was
applied, which effects were observed, and whether qualified containment
governed the near-boundary execution.
