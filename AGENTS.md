# Project status reporting

For project-progress or project-status requests, read
`docs/current_status_and_roadmap.md` first and organize the answer only around:

1. the reproduced SABER attack and its attack-success rate;
2. the completed four-arm result for the original method;
3. the current optimization result for the new method;
4. the final experiments that are still missing.

Do not enumerate archived failed experiments or intermediate versions unless the user explicitly asks for history,
failure analysis, or a specific version. `docs/progress_and_plan.md`, `docs/failure_lessons.md`, historical checkpoints,
and frozen non-pass artifacts are audit material rather than default status sources.

Preserve historical protocols, results, checksums, and non-pass classifications for reproducibility. Documentation
cleanup does not authorize deleting or reinterpreting those artifacts.
